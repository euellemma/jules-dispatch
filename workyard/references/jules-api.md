# Jules API Reference

Essential API operations for the orchestrator. Full docs at https://developers.google.com/jules/api

## Session Limits

| Plan | Tasks/Day | Concurrent |
|------|-----------|------------|
| Free | 15 | 3 |
| Pro | 100 | 15 |
| Ultra | 300 | 60 |

Sessions can be **resumed** after completion via `sendMessage`. Resuming does NOT count as a new session against the daily limit. This is critical for session economy — always prefer resuming over creating new sessions.

## Create Session

```
POST https://jules.googleapis.com/v1alpha/sessions
```

```json
{
  "prompt": "string — The full prompt for the session. This is where you inject the template.",
  "sourceContext": {
    "source": "sources/github/{owner}/{repo}",
    "githubRepoContext": {
      "startingBranch": "string — base branch, e.g., 'main'"
    }
  },
  "automationMode": "AUTO_CREATE_PR | NO_AUTO_PR",
  "requirePlanApproval": "boolean — if true, plan must be approved before implementation",
  "title": "string — human-readable session title"
}
```

### Key Parameters

- **prompt**: The entire instruction set for the session. Construct this from the templates in `flows/`. Include all context the session needs — it has no other information about the project.
- **automationMode**: 
  - `AUTO_CREATE_PR` — Session automatically creates a PR when done (recommended)
  - `NO_AUTO_PR` — Session creates a branch but no PR
- **requirePlanApproval**: 
  - `true` — Session pauses after generating a plan. Orchestrator must call `approvePlan` to proceed.
  - `false` — Session proceeds from plan to implementation automatically.
  - Default value when not specified: `true`

### Source Lookup

Before creating a session, you may need to find the source name:

```
GET https://jules.googleapis.com/v1alpha/sources
```

Returns available GitHub repos that Jules can access. The `source` field in `sourceContext` uses the format `sources/github/{owner}/{repo}`.

## Approve Plan

```
POST https://jules.googleapis.com/v1alpha/sessions/{session_id}:approvePlan
```

No body required. Approves the latest plan generated by the session, allowing it to proceed to implementation.

Only call this when `requirePlanApproval: true` was set on session creation AND the session has generated a plan (visible via activities).

## Send Message

```
POST https://jules.googleapis.com/v1alpha/sessions/{session_id}:sendMessage
```

```json
{
  "prompt": "string — The follow-up message"
}
```

**Critical feature**: This works on completed sessions too. This is how you **resume** a session — sending a message to a completed session causes it to continue working. This does NOT create a new session.

Use cases:
- Correct a session's approach (see `flows/correct-session.md`)
- Ask a session to fix CI failures
- Ask a session to continue partial work
- Ask a session to resolve merge conflicts

## Get Session

```
GET https://jules.googleapis.com/v1alpha/sessions/{session_id}
```

Returns session state including:
- Current status (active, completed, etc.)
- Output PRs (if any)
- Source context

## List Sessions

```
GET https://jules.googleapis.com/v1alpha/sessions?pageSize=50
```

List all sessions. Use `pageToken` for pagination. Useful for finding sessions by title or checking across repos.

## List Activities

```
GET https://jules.googleapis.com/v1alpha/sessions/{session_id}/activities?pageSize=50
```

Returns the activity stream — the real-time record of what the session has done:

| Activity Type | What it means |
|---------------|---------------|
| `planGenerated` | Session produced a plan. Review and approve if `requirePlanApproval: true`. |
| `progressUpdated` | Session made progress. Contains title and description. |
| `changeSet` | Session created file changes. Contains git patch data. |
| `bashOutput` | Session ran a command. Contains command and output. |
| `sessionCompleted` | Session finished. Check for PR in the output. |

This is your primary monitoring tool. Poll periodically to track session progress and detect completion.

## Authentication

All API calls require an API key in the `X-Goog-Api-Key` header:

```
X-Goog-Api-Key: YOUR_JULES_API_KEY
```

Generate keys at https://jules.google.com/settings#api

## Rate Limits and Concurrency

- Sessions are processed asynchronously — creating a session returns immediately
- Concurrent session limits apply (3/15/60 depending on plan)
- Poll for completion using `sessions.get` or `sessions.activities.list`
- Session creation is fast; implementation takes time based on task complexity
- Plan approval adds a round-trip; use `requirePlanApproval: false` for speed when appropriate

## Common Patterns

### Create and Monitor

```
1. Create session with sessions.create
2. Poll sessions.get every 30-60 seconds
3. When status changes, check activities
4. If planGenerated and requirePlanApproval: call approvePlan
5. Continue polling until sessionCompleted
6. Extract PR URL from session output
```

### Resume for Correction

```
1. Session completed but CI failed
2. Get failure details from GitHub Checks API
3. Call sessions.sendMessage with corrective instructions
4. Poll for new completion
5. Check for updated PR
```

### Parallel Dispatch

```
1. Create N sessions simultaneously (respecting concurrency limits)
2. Track session IDs in progress.md
3. Poll each session's activities independently
4. Approve plans as needed
5. When all complete, proceed to merge workflow
```

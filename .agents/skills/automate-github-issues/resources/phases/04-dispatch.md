# Phase 4: Dispatch (`fleet-dispatch.ts`)

The **Dispatch** phase scales the implementation effort. It reads the validated `issue_tasks.json` and uses the `@google/jules-sdk` to spawn simultaneous, parallel Jules coding sessions—one for each task.

## Code Execution Path

1. Immediately following the Validate phase in `fleet-dispatch.ts`.
2. It calls `jules.all()` mapping over the `tasks` array.
3. It writes the resulting session IDs to a mapping file for Phase 5.

```typescript
// scripts/fleet-dispatch.ts (Snippet)

const sessions = await jules.all(tasks, task => ({
  prompt: task.prompt,
  source: {
    github: repoInfo.fullName,
    baseBranch, // Usually 'main'
  }
}))

const sessionResults: Array<{ taskId: string; sessionId: string }> = [];
for await (const session of sessions) {
  const taskId = tasks[sessionResults.length]?.id ?? "unknown";
  sessionResults.push({ taskId, sessionId: session.id });
  console.log(`Task ${taskId} → Session ${session.id}`);
}

// Write session mapping for fleet-merge.ts
const sessionsPath = path.join(fleetDir, "sessions.json");
await Bun.write(sessionsPath, JSON.stringify(sessionResults, null, 2));
```

## Inputs
* The validated `.fleet/YYYY_MM_DD/issue_tasks.json`.
* Target repository and base branch.

## The Context Sent to Jules (The Prompt)

For **every** task in the array, an independent Jules agent is booted up. These agents have no shared context; they cannot communicate with each other, and they do not know about the other tasks running concurrently.

They receive only the codebase (at `baseBranch`) and the highly detailed `prompt` string generated by the Staff Engineer agent in Phase 2.

Here is an example of the **exact prompt** an agent might receive:

```markdown
Task: Fix Cart 500 Error during simultaneous checkout
Root Cause: `src/cart.ts` throws a 500 error on `inventory_check` if the item count reaches 0 exactly during the API call.

Files to modify: `src/cart.ts`
Test files to modify: `tests/cart.test.ts`

**Proposed Implementation:**
Update `checkout()` in `src/cart.ts` to catch the `InventoryExhaustedError` and gracefully return a 409 Conflict with a user-friendly message, rather than letting the 500 propagate.

```typescript
// src/cart.ts implementation target:
try {
  await inventoryCheck(items);
} catch (e) {
  if (e instanceof InventoryExhaustedError) {
    return res.status(409).json({ error: "Item went out of stock during checkout." });
  }
  throw e;
}
```

**Test Scenarios:**
1. Mock `inventoryCheck` to throw `InventoryExhaustedError` and assert a 409 response is returned.

**FILE BOUNDARY RULE:**
You may ONLY modify the files listed above (`src/cart.ts`, `tests/cart.test.ts`). If a test file outside your boundary fails, you must make your source changes backward-compatible so the existing test passes unmodified. Do NOT rename, move, or delete any files outside your boundary.
```

## Outputs
* **`sessions.json`:** A file mapping `{ "taskId": "task-cart-fix", "sessionId": "sess_123abc" }`.
* **GitHub PRs:** Each spawned session will autonomously branch off `main`, commit the requested code, and open a Pull Request authored by the `google-labs-jules[bot]` account.
